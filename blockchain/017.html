1. Merkle Tree 是什么

Merkle Tree（默克尔树）是一种哈希二叉树，由 Ralph Merkle 于 1979 年提出。 它将一批数据块（叶子节点）逐层两两哈希，最终汇聚成一个根哈希（Merkle Root）。 其核心价值在于：用一个短小的根哈希代表整批数据，并能以 O(log n) 的代价证明某个数据块属于这批数据。

典型应用
  • 区块链：比特币使用 Merkle Tree 汇总区块交易，区块头保存 Merkle Root；以太坊则使用 Merkle-Patricia Trie（MPT）等认证数据结构，其交易根并不是本文这种普通二叉 Merkle Tree。
  • 内容寻址 / 数据完整性：Git、IPFS 等系统广泛使用 Merkle DAG / 哈希链接等结构来验证对象之间的完整性；它们并不都等同于本文的二叉 Merkle Tree。
  • 证书透明性：Certificate Transparency（CT）使用 Merkle Tree（RFC 6962 中定义的 Merkle Hash Tree）记录日志条目，并通过 Merkle Proof 支持包含性证明。
  • 零知识证明：Merkle Tree 是许多 ZK 方案的承诺（commitment）基础。

2. 核心性质与术语

术语含义
Leaf（叶子节点）底层数据块的哈希，即 H(data)
Internal Node（内部节点）两个子节点哈希拼接后再哈希：H(left || right)
Merkle Root（根哈希）树顶唯一节点，代表整棵树的指纹
Merkle Proof / Audit Path从某个叶子到根所不经过的兄弟节点哈希序列，用于证明该叶子属于树
Domain Separation区分叶子哈希与内部节点哈希（如叶子加 0x00 前缀、内部加 0x01），防止第二原像攻击
安全提醒：第二原像攻击（Second Preimage Attack）

如果叶子哈希与内部节点哈希使用完全相同的算法，攻击者可以把一对 (H(A), H(B)) 伪装成一个叶子数据 C， 使得 H(C) = H(H(A)||H(B))，从而伪造一个不存在的叶子。

防御：对叶子和内部节点使用不同的哈希前缀（域分离），例如：

  • 叶子：H(0x00 || data)
  • 内部：H(0x01 || leftHash || rightHash)

3. 场景一：2^n 个叶子节点（完美二叉树）PERFECT

当叶子数量恰好是 2 的幂（如 2、4、8、16…）时，Merkle Tree 是一棵完美二叉树：每一层的节点数都是上一层的一半，最终汇聚到唯一的根。

3.1 构建步骤（以 4 个叶子为例）

1
计算叶子哈希：对每个原始数据块分别哈希，得到 4 个叶子节点 L0, L1, L2, L3。
2
第 1 层聚合：相邻两两配对，N0 = H(L0 || L1)，N1 = H(L2 || L3)，得到 2 个内部节点。
3
第 2 层聚合：再将这 2 个节点配对，Root = H(N0 || N1)，得到 Merkle Root。
4
终止：当某层只剩 1 个节点时，该节点即为根，构建结束。

完美树的规律
  • 叶子数 = 2^n，则树高 = n（从叶子到根经过 n 次哈希）。
  • 当叶子数为 2^n 时，总节点数 = 2^(n+1) - 1；这个公式不适用于奇数复制等非完美树场景。
  • 每一层节点数恰好是上一层的 1/2，无需奇数节点处理。

4. 场景二：非 2^n 个叶子节点（不平衡树）IMPERFECT

实际场景中，叶子数量往往不是 2 的幂（例如比特币区块中有 1237 笔交易）。 此时无法直接两两配对到根，需要采用特定策略处理"落单"的节点。业界主要有三种方案：

策略做法采用者特点
① 复制最后节点
（Odd Duplication）		 某层节点数为奇数时，将最后一个节点复制一份与自己配对 比特币（Bitcoin-style） 实现简单；但“复制”会让某些叶子的证明路径包含自配对。注意：复制后未必形成数学意义上的“完美二叉树”，只是每层都通过复制补齐为偶数。
② 不平衡树 / 直接提升
（Promote Odd Node）		 奇数节点不复制，直接进入下一层，后续再参与配对 一种通用构建方式；具体系统必须以其协议规范为准 不会因为奇数节点而复制哈希，但 Proof 编码必须能够表达不同层级的结构
③ 固定容量 / 零值填充
（Zero Padding）		 按照协议约定的空节点值，把未使用位置填充到固定容量 部分固定深度 Merkle Tree / Sparse Merkle Tree 等方案 深度和空节点值通常由协议预先规定；空节点并不等于普通业务数据，编码规则必须明确

复制策略的副作用

由于 N2 = H(L4 ‖ L4)，知道 L4 的验证者当然可以计算 N2。 这并不是“泄露秘密”，因为 Merkle Tree 的叶子通常本来就不是保密机制；真正需要保证的是哈希函数的抗碰撞性以及树构建规则的一致性。 复制策略的主要特点是：

  • 树中存在重复使用的节点值，Proof 中可能出现“自己和自己配对”的步骤。
  • 比特币的实现中，只有当节点数为奇数时才复制最后一个节点，且复制发生在每一层。
  • 对于 2^n + 1 个叶子（如 5、9、17…），最后一个叶子会在每一层都被复制，形成一条"复制链"。

零值填充的注意事项
  • 零值叶子必须是公开约定的常量，不能是真实数据，否则攻击者可以插入零值数据伪造叶子。

4.4 2^n + 1 个叶子的特殊形态

当叶子数恰好为 2^n + 1（如 3、5、9、17…）时，在本文采用的“每层奇数则复制最后节点”规则下， 最后一个叶子会经历多次自复制，形成一条“复制链”。这是理解该构建规则的典型例子。 注意：这不是所有 Merkle Tree 的通用规律，也不应泛化为所有区块链实现。

以 3 个叶子为例（2^1 + 1）：

  • 第 1 层：N0 = H(L0‖L1)，N1 = H(L2‖L2)（复制 L2）
  • 根：Root = H(N0 ‖ N1)

5. Merkle Proof：如何证明一个叶子存在

Merkle Proof（也叫 Audit Path / Inclusion Proof）回答的问题是： "我手上有一个数据块 D 和一个根哈希 Root，如何在不下载整棵树的情况下，证明 D 对应的叶子在这棵树里？"

5.1 Proof 的构成

证明者需要提供从目标叶子到根路径上，每一层的兄弟节点哈希。 验证者拿着目标叶子哈希，逐层与兄弟节点哈希配对计算，最终得到根哈希，与已知 Root 比较即可。

核心直觉

要计算根，你需要路径上每一层的"另一个孩子"。这些兄弟节点的哈希就是 Proof 的全部内容。 Proof 的长度 = 树高 = O(log n)，与叶子总数无关。

  • 第 2 层兄弟：N1（N0 的右兄弟，N0 = H(L0‖L1)）

Proof 的编码方式

实际实现中，Proof 通常编码为一个哈希数组 + 一个位置标记（左/右），例如：

interface MerkleProof {
  siblingHashes: Hash[];   // 从叶子到根的兄弟节点哈希
  positions: boolean[];     // true=兄弟在右边, false=兄弟在左边
}

或者用更紧凑的方式：在每个兄弟哈希前加 1 字节标记（0x00=左，0x01=右）。

6. Proof 验证算法

6.1 验证流程伪代码

function verify(leafHash: Hash, proof: MerkleProof, root: Hash): boolean {
  let current = leafHash;
  for (let i = 0; i < proof.siblingHashes.length; i++) {
    const sibling = proof.siblingHashes[i];
    const siblingIsRight = proof.positions[i];
    if (siblingIsRight) {
      current = hash(concat(current, sibling));  // 自己在左，兄弟在右
    } else {
      current = hash(concat(sibling, current));  // 兄弟在左，自己在右
    }
  }
  return current === root;
}

为什么 Merkle Tree 如此强大

对比直接下载全部数据进行验证，Merkle Inclusion Proof 只需要目标数据对应的哈希路径信息。 对于平衡二叉树，Proof 大小为 O(log n)。例如 n = 1,000,000 时，二进制对数约为 20； 如果每个兄弟哈希为 32 字节，则仅哈希部分约为 640 字节，此外还需要位置/方向信息。 这也是 Merkle Proof 适合轻量验证的重要原因之一。

8. 完整参考实现（TypeScript）

以下实现采用“奇数时复制最后节点”的 Bitcoin-style 构建规则，包含构建、Proof 生成与验证。 注意：由于代码额外采用了叶子/内部节点域分离，因此它不是 Bitcoin Core 的字节级兼容实现；这里只借鉴其奇数节点复制规则。

import { createHash } from "crypto";

type Hash = Buffer;

/** 域分离：叶子哈希加 0x00 前缀，内部节点加 0x01 前缀 */
function hashLeaf(data: Buffer): Hash {
  return createHash("sha256").update(Buffer.from([0x00])).update(data).digest();
}

function hashInternal(left: Hash, right: Hash): Hash {
  return createHash("sha256")
    .update(Buffer.from([0x01]))
    .update(left)
    .update(right)
    .digest();
}

export interface MerkleProof {
  /** 从叶子层到根层的兄弟节点哈希 */
  siblingHashes: Hash[];
  /** 对应兄弟是否在右侧（true=右，false=左） */
  siblingOnRight: boolean[];
}

export class MerkleTree {
  private leaves: Hash[] = [];
  private layers: Hash[][] = []; // layers[0] = 叶子层，layers[last] = [root]

  constructor(dataBlocks: Buffer[]) {
    if (dataBlocks.length === 0) throw new Error("Cannot build tree with zero leaves");
    this.leaves = dataBlocks.map(hashLeaf);
    this.build();
  }

  /** 构建树：逐层两两配对，奇数时复制最后一个节点 */
  private build(): void {
    this.layers = [this.leaves];
    let current = this.leaves;
    while (current.length > 1) {
      const next: Hash[] = [];
      for (let i = 0; i < current.length; i += 2) {
        const left = current[i];
        const right = i + 1 < current.length ? current[i + 1] : left; // 奇数时复制自己
        next.push(hashInternal(left, right));
      }
      this.layers.push(next);
      current = next;
    }
  }

  getRoot(): Hash {
    return this.layers[this.layers.length - 1][0];
  }

  /** 为指定索引的叶子生成 Merkle Proof */
  getProof(index: number): MerkleProof {
    if (index < 0 || index >= this.leaves.length) {
      throw new Error(`Leaf index ${index} out of range`);
    }
    const siblingHashes: Hash[] = [];
    const siblingOnRight: boolean[] = [];
    let idx = index;
    for (let layer = 0; layer < this.layers.length - 1; layer++) {
      const currentLayer = this.layers[layer];
      const isRight = idx % 2 === 1;
      const siblingIdx = isRight ? idx - 1 : idx + 1;
      // 处理最后一个落单节点：其兄弟是自己（复制）
      const sibling = siblingIdx < currentLayer.length ? currentLayer[siblingIdx] : currentLayer[idx];
      siblingHashes.push(sibling);
      siblingOnRight.push(!isRight); // 如果自己在左(isRight=false)，兄弟在右
      idx = Math.floor(idx / 2);
    }
    return { siblingHashes, siblingOnRight };
  }

  /** 验证某个数据块的 Proof */
  static verify(data: Buffer, proof: MerkleProof, root: Hash): boolean {
    let current = hashLeaf(data);
    for (let i = 0; i < proof.siblingHashes.length; i++) {
      const sibling = proof.siblingHashes[i];
      current = proof.siblingOnRight[i]
        ? hashInternal(current, sibling)
        : hashInternal(sibling, current);
    }
    return current.equals(root);
  }
}

// ========== 使用示例 ==========
const blocks = ["a", "b", "c", "d", "e"].map((s) => Buffer.from(s));
const tree = new MerkleTree(blocks);
const root = tree.getRoot();
const proof = tree.getProof(4); // 证明 "e" 存在
const isValid = MerkleTree.verify(Buffer.from("e"), proof, root);
console.log("Root:", root.toString("hex"));
console.log("Proof valid:", isValid); // true

实现要点总结
  1. 域分离：叶子和内部节点使用不同前缀，避免不同节点类型之间的编码歧义并增强结构安全性。
  2. 复制策略：每层遇到奇数节点时，最后一个节点与自己配对。
  3. Proof 生成：从目标叶子索引出发，逐层找兄弟节点，记录兄弟哈希和左右位置。
  4. Proof 验证：静态方法，只需数据、Proof、根哈希三者，无需整棵树。
  5. 落单节点的 Proof：在本文的复制规则下，目标节点如果是某层最后一个落单节点，其兄弟可按协议规则视为自身；实现时必须让证明生成和验证使用完全相同的规则。
