EIP-2612 Permit 技术调研报告

一、什么是 EIP-2612 Permit

EIP-2612（ERC20 Permit） 是以太坊改进提案，为标准 ERC20 代币增加链下签名授权标准。 它基于 EIP-712 结构化可读签名，允许代币所有者不用发送链上 approve 交易， 通过钱包离线签名生成授权凭证；任意账户（用户、中继Relayer、合约）可将签名上链调用 permit() 设置授权额度 allowance。

最早由 MakerDAO 的 DAI 代币率先实现 permit 模式，后标准化为 EIP-2612；目前 DAI、USDC（v2+）、UNI、LINK、AAVE 等主流代币已广泛支持。

二、传统 ERC20 approve 原生机制存在什么痛点

flowchart LR A[用户Alice] -->|"TX1：approve(DEX合约,金额)
用户支付Gas"| B[ERC20合约
更新allowance] B -->|等待区块确认| A A -->|"TX2：调用DEX.swap()
DEX内部执行transferFrom"| D[代币划转完成]
  1. 必须两笔独立链上交易：先 approve，再执行swap/deposit；交互步骤长、等待确认时间久。
  2. 授权交易必须由所有者EOA发起：approve依赖 msg.sender，无法由第三方代发。
  3. 用户必须持有原生Gas代币（ETH） 才能发起授权；新用户只有代币、没有ETH时完全无法授权。
  4. 两次Gas消耗，两笔交易均需成功才能完成操作，任一交易失败（如网络拥堵、Gas不足）将导致整个流程中断，需重新开始。

核心接口标准定义

interface IERC20Permit {
    function permit(
        address owner,      // 代币持有者
        address spender,    // 被授权合约/地址
        uint256 value,      // 授权额度
        uint256 deadline,   // 签名过期时间戳
        uint8 v, bytes32 r, bytes32 s // ECDSA签名
    ) external;

    // 获取当前nonce（防重放）
    function nonces(address owner) external view returns (uint256);
    // EIP712域分隔符，防止跨合约/跨链签名复用
    function DOMAIN_SEPARATOR() external view returns (bytes32);
}

五、EIP-2612 解决的核心问题总结

  • ✅ 消除“两次交易”痛点：授权和业务操作合并为一笔链上交易，大幅优化DeFi用户体验；
  • ✅ 支持Gasless无Gas授权（元交易基础），解决“有代币但没有ETH无法交互”的新用户门槛；
  • ✅ 授权动作与提交动作解耦：谁都可以提交签名上链，催生中继Relayer服务；
  • ✅ EIP712标准化可读签名，相比原始hash签名，钱包可以展示授权明细，提升透明度；
  • ✅ 标准化安全机制：nonce防重复使用签名、deadline限制授权有效期、domain separator防止跨合约签名劫持。

六、安全风险与注意事项（重点）

⚠️ 主要风险点

  1. 钓鱼签名攻击：Permit只是签名，不会弹出Gas交易弹窗，用户警惕性更低；恶意DApp诱导签署大额授权签名后，可立刻调用transferFrom盗币；
  2. 签名有效期风险：若deadline设置极大（永久有效），签名一旦泄露可长期被攻击者提交；建议有效期控制在几十分钟~几小时；
  3. 签名泄露与被抢先提交：签名在链下传递（如通过 HTTP API 发给 Relayer）或出现在待处理交易中时，任何获取到该签名的第三方可立即调用 permit() 抢先消耗 nonce。若原始交易包含后续业务操作（如 swap），将因 nonce 已失效而回滚；若签名授权了恶意地址为 spender，则可能被盗币；
  4. 不要混用 permit + 无限授权（type(uint256).max），一旦签名泄露损失巨大；
  5. 仅支持实现EIP-2612的代币合约，普通ERC20不具备permit函数。

七、典型业务场景

  • DEX一键Swap：签名Permit，单笔交易完成授权+兑换；
  • Lending借贷平台存款：Permit + deposit合并调用；
  • 元交易Gasless产品：第三方Relayer代用户发送permit交易；
  • 钱包/支付应用：降低新用户准入门槛，不用预先购买ETH；

八、延伸：EIP-2612 vs Permit2 简要区分

EIP-2612：代币合约原生内置，仅针对当前代币生效； Permit2（Uniswap）：独立通用中介合约，单一签名支持多币种、批量授权，不依赖代币是否实现EIP2612。

九、结论

EIP-2612 Permit 没有修改 ERC20 转账逻辑，只是新增一套授权通道。它从根本上解决传统approve“双交易、强制用户付Gas”的巨大UX短板， 是DeFi生态中Gasless交互、元交易基础设施最重要标准之一；目前是主流新项目ERC20代币标配扩展。
