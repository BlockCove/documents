一、什么是 Uniswap？—— AMM 自动做市商

1.1 传统交易所 vs DEX

🏦 传统订单簿交易所（如 Binance、NYSE）

  • • 买卖双方各自挂单，撮合引擎匹配成交
  • • 需要做市商提供流动性，否则深度差、滑点大
  • • 依赖中心化服务器，存在单点故障和审查风险

🔗 DEX / AMM（如 Uniswap）

  • • 没有订单簿，没有撮合引擎
  • • 流动性由数学公式自动定价，任何人可成为 LP
  • • 完全链上运行，去中心化、无需许可、透明可审计

1.2 AMM 的核心思想

AMM（Automated Market Maker，自动做市商） 用数学公式替代传统订单簿，实现机器自动报价。

核心思路：

🧠 交易池 = 一个装满两种代币的"水缸"

• 用户往池子里存入代币 A，按公式计算出能拿走多少代币 B

• 池子里的代币比例决定价格，交易行为改变比例 → 改变价格

• 任何人都可以存入两种代币成为 LP（流动性提供者），赚取交易手续费

二、为什么需要 V3？—— V2 的局限与 V3 的突破

2.1 V2 的恒定乘积公式

Uniswap V2 的核心是 恒定乘积公式：

$$x \cdot y = k$$

\(x\) = 池中 token0 数量，\(y\) = 池中 token1 数量，\(k\) = 常数

这意味着：

  • • 价格由比例决定：\(P = \frac{y}{x}\)（1 个 token0 值多少 token1）
  • • 交易改变价格：买入 token1 → 池中 token1 减少、token0 增加 → P 下降（token1 变贵，token0 变便宜）
  • • 曲线永不归零：无论交易量多大，池子永远不会被掏空（只会越来越贵）

📐 直观理解恒定乘积曲线

在 \(x \cdot y = k\) 曲线上，价格 = 切线斜率的绝对值。当 x 很小（token0 稀缺），y 很大（token1 泛滥），P = y/x 极高——这意味着 越稀缺的代币越贵，符合经济学直觉。

2.2 V2 的根本问题：资本效率极低

⚠️ V2 的致命缺陷

V2 的流动性覆盖 0 到 ∞ 全部价格区间。但大部分价格区间永远不会被触及。

例如 USDC/DAI 稳定币对，价格永远在 0.99~1.01 之间波动，V2 的流动性却散落在 0 到 ∞，99% 以上的资金在闲置，从未参与交易，也不产生手续费收入。

2.3 V3 的解决方案：集中流动性

V3 的核心创新：LP 可以自定义提供流动性的价格区间。

V2：全局流动性

流动性 L 覆盖全部价格，大部分闲置

资金利用率 ≈ 0%~10%

V3：集中流动性

LP 自选区间 [Plow, Phigh]，资金集中在交易活跃的价格附近

同样的资金 → 区间内流动性深度更高 → 资本效率提升 最高 4000 倍

🎯 类比理解

V2 像把一桶水倒在整个足球场上——大部分区域是干的；V3 像把同一桶水集中倒在球门区——深度大大增加。同样的资金，在更窄的价格区间内提供更高的交易深度。

三、V3 核心机制：Tick 与集中流动性

3.1 Tick：价格的离散化刻度

V3 将连续的价格空间切分为离散的刻度——Tick。每条 Tick 对应一个精确的价格：

$$P(i) = 1.0001^i$$

\(i\) = tick 索引，是一个整数；\(P\) = token0 相对于 token1 的价格

🔢 为什么选择 1.0001？

  • • 每个 tick 价格相差 0.01%（1 bps）——足够精细
  • • \(1.0001^{6932} \approx 2\)：每 +6932 tick，价格翻倍
  • • \(1.0001^{-6932} \approx 0.5\)：每 -6932 tick，价格减半
  • • 这样的设计确保任意两个 tick 之间的价格差异精确可控

3.2 Tick Spacing（步长）—— 为什么需要它？

要解决什么问题？

理论上每个 tick（0.01% 价格间隔）都可以作为 LP 仓位边界。但如果允许在任意 tick 上设边界：

  • • 流动性碎片化：L 散落在几十万个 tick 上，swap 时每跨一个 tick 都要消耗 GAS 更新状态
  • • 大额 swap 可能跨越成千上万个 tick → GAS 直接爆掉

Tick Spacing 的解决方案：LP 仓位边界只能设在 Spacing 的整数倍上。这样 tick 被"合并"成更大的步长，swap 跨一次跳过一个 Spacing 的距离，大幅减少跨 tick 次数 → 降低 GAS。

为什么不同费率用不同 Spacing？

这是一个 精度 vs GAS 的权衡：

  • • 低费率池（0.01%、0.05%）：交易量大、价格稳定，LP 需要紧贴市价做市 → 小 Spacing，允许更精确的区间设置
  • • 高费率池（1%）：交易量小、波动大，swap 不会频繁发生 → 大 Spacing，牺牲精度换 GAS 节省

举例：若没有 Spacing 限制，一场大额 swap 在 USDC/ETH 池中可能跨过上万个 tick，每次跨 tick 写存储成本约 5000 gas，总额轻易超过区块 gas limit。

不同手续费层级的池子，LP 仓位边界的 tick 必须是 Spacing 的整数倍：

手续费层级 Tick Spacing 可设置的 tick 示例 适用场景
0.01%（1 bps） 1 ..., -10, -9, -8, ... 稳定币对（如 USDC/DAI），价格波动极小
0.05%（5 bps） 10 ..., 202900, 202910, 202920, ... 主流交易对（如 USDC/ETH），波动温和
0.3%（30 bps） 60 ..., 202860, 202920, 202980, ... 普通交易对
1%（100 bps） 200 ..., 202800, 203000, 203200, ... 高波动 / 长尾代币

* 本案例使用 0.05% 费率池，Spacing=10，所以 tick 边界只能是 ..., 202900, 202910, 202920, ... 这也是为什么案例中区间以 10 为步长。

3.3 区间流动性的运行规则

核心规则：

  1. 1. 池子被 Tick 切分成一段段独立的价格区间，每个区间拥有独立的流动性 L
  2. 2. 只有当前市场 Tick 落在 LP 设置的区间内时，该 LP 的资金才参与交易、赚取手续费
  3. 3. 价格走出区间后，LP 仓位变为单边资产（全是 token0 或全是 token1），不再参与 Swap
  4. 4. Swap 过程中价格触碰 Tick 边界 → 触发 跨 Tick（Cross Tick），切换当前生效的流动性 L
  5. 5. 同一区间内的所有 LP 仓位共享流动性 L，按比例分配手续费

🔍 规则③深入：单边资产是怎么"变"出来的？—— 不是设变量，是数学的自然结果

很多人的直觉是"价格走出区间后，合约把一边的代币数量设成 0"。完全不是这样。单边是区间内 swap 过程自然消耗完的——跟 V2 永远耗不尽一个道理，但 V3 的"虚拟准备金"让耗尽发生在有限价格点。

用 4.2 节的公式代入边界价格就清楚了：

价格跌到下界 P = P_a（token1 全耗尽→全是 token0）

代入 y_real 公式：

\(y_{\text{real}} = L(\sqrt{P_a} - \sqrt{P_a}) = 0\)

而 x_real 仍有剩余：

\(x_{\text{real}} = L(1/\sqrt{P_a} - 1/\sqrt{P_b}) > 0\)

→ 仓位 token1 归零，只剩 token0，不参与后续 swap

价格涨到上界 P = P_b（token0 全耗尽→全是 token1）

代入 x_real 公式：

\(x_{\text{real}} = L(1/\sqrt{P_b} - 1/\sqrt{P_b}) = 0\)

而 y_real 仍有剩余：

\(y_{\text{real}} = L(\sqrt{P_b} - \sqrt{P_a}) > 0\)

→ 仓位 token0 归零，只剩 token1，不参与后续 swap

核心逻辑：虚拟准备金 x_virtual 和 y_virtual 把恒定乘积曲线"平移"了——

• V2 曲线两端渐近 x=0 和 y=0，永远碰不到（价格需到 0 或 ∞）

• V3 曲线两端在 P_a 和 P_b 处精确触达 x=0 或 y=0——这是虚拟准备金平移导致的效果

所以"单边"不是合约检测价格后把某边清零，而是在 swap 过程中，价格推到 P_a 或 P_b 的那一刻，那一端的代币恰好被全部换出去了。

💰 规则⑤深入：手续费如何分配？—— 跨多个 Spacing 的仓位也能准确计算

LP 仓位可以跨多个区间

比如一个 LP 仓位设在 [Tick 100, Tick 200]（Spacing=10，覆盖 10 个区间），他的 同一个 L 同时贡献给这 10 个区间的每一个。就像往一条河的不同段各倒了一桶等量的水。

手续费按区间独立累积

每个 tick 区间维护自己的 feeGrowth（每单位 L 累积的手续费）。swap 发生在哪个区间，手续费就记在哪个区间上。

LP 能赚多少？—— 所在区间的费用按比例加总

LP 在它覆盖的每个区间内按 L 比例分手续费，加总即为总收益。合约用 "fee growth inside − 入场时的 fee growth 快照" 来计算，不遍历区间，O(1) 搞定。

举例：Alice 仓位 [Tick 0, Tick 20]，L=100；Bob 仓位 [Tick 10, Tick 30]，L=50。

区间 [10, 20] 内 L_total = 150（两人重叠），该区间产生了 15 USDC 手续费：

• Alice 拿走：15 × 100/150 = 10 USDC   |   Bob 拿走：15 × 50/150 = 5 USDC

区间 [0, 10] 内只有 Alice（L=100），手续费全归她；区间 [20, 30] 内只有 Bob（L=50），手续费全归他。

3.4 流动性净变化：liquidityNet 与已初始化 Tick

每个 Tick 上记录了一个 liquidityNet 值：当价格从左向右跨越一个 Tick 时，流动性增加/减少 liquidityNet。这允许 swap 过程中高效地累加/减去流动性，而无需遍历所有 LP 仓位。

💡 关键设计

V3 只维护 已初始化 的 Tick（有 LP 在其上设置了仓位边界）。swap 循环时，价格在已初始化的 Tick 之间"跳跃"，跳过大量未初始化的 Tick，极大节省 GAS。

3.5 L 到底是什么？—— 流动性的本质与变化规律

① L 的定义

V2 中：\(L = \sqrt{x \cdot y} = \sqrt{k}\)。L 是恒定乘积曲线的几何参数——L 越大，曲线越"鼓"，相同交易量的滑点越小。

V3 中：L 含义完全一致，只是用虚拟准备金替代真实准备金：

$$L = \sqrt{(x_{\text{real}} + x_{\text{virtual}}) \cdot (y_{\text{real}} + y_{\text{virtual}})}$$

所以 L 就是流动性本身，单位是 \(\sqrt{\text{token0} \cdot \text{token1}}\)。同一区间内 L 越大 = 深度越好 = 滑点越低。

② Swap 过程中 L 变不变？—— 不变！

在同一个 Tick 区间内 swap，只改变准备金在 x 和 y 之间的分配，L 保持恒定。

类比：V2 的 swap 沿着 \(x \cdot y = L^2\) 曲线移动，L 不变；V3 区间的 swap 沿着 \((x_{\text{real}}+x_{\text{virtual}})(y_{\text{real}}+y_{\text{virtual}}) = L^2\) 移动，L 同样不变。这就是为什么 4.3 节的 swap 公式中 L 是常数。

③ 跨 Tick 时 L 如何变化？—— 由 liquidityNet 决定

L 只在价格跨越 Tick 边界时改变。每次跨 Tick，合约读取该 Tick 上记录的 liquidityNet：

$$L_{\text{new}} = L_{\text{old}} + \text{liquidityNet}$$

注：这是从左→右跨 Tick 的情况。若从右→左（如 USDC 买入 ETH），liquidityNet 符号取反。

liquidityNet 是怎么来的？每个 LP 开设仓位时，会在区间两端的 Tick 上累加/减去自己的 L：

  • • 在 tickLower（下界）：liquidityNet += L_position——从左→右进入区间，L 应增加
  • • 在 tickUpper（上界）：liquidityNet -= L_position——从左→右离开区间，L 应减少

⚠️ 注意方向：以上约定是"从左→右"（tick 增大）。若价格从右→左移动（如本案例 USDC 买入 ETH，tick 减小），合约会把 liquidityNet 的符号取反：

\(L_{\text{new}} = L_{\text{old}} - \text{liquidityNet}\) （从右→左时）

这样设计的好处：同一个 liquidityNet 值可以同时服务于两个方向的 swap，只需多一次符号判断。

💡 具体例子——一看就懂

假设只考虑三个 tick 位置，有两个 LP：

  • • Alice：仓位 [Tick 0, Tick 20]，L = 100
  • • Bob：仓位 [Tick 10, Tick 30]，L = 50

创建仓位时，在 tick 边界上写入 liquidityNet：

Tick谁设的liquidityNet含义
0Alice 下界+100Alice 从这里进入
10Bob 下界+50Bob 从这里进入
20Alice 上界−100Alice 从这里退出
30Bob 上界−50Bob 从这里退出

价格从左→右移动时（L_new = L_old + liquidityNet）：

价格区间跨过的 TickL 的计算活跃 LP
0~10—0 + 100 = 100Alice
10~20Tick 10100 + 50 = 150Alice + Bob
20~30Tick 20150 + (−100) = 50Bob
>30Tick 3050 + (−50) = 0无人

价格从右→左移动时（L_new = L_old − liquidityNet，符号取反）：

价格区间跨过的 TickL 的计算（−liquidityNet）活跃 LP
>30—0 − 0 = 0无人
20~30Tick 300 − (−50) = 50Bob 进来
10~20Tick 2050 − (−100) = 150Alice 也进来
0~10Tick 10150 − 50 = 100Bob 退出
<0Tick 0100 − 100 = 0Alice 也退出

一句话：liquidityNet 把"哪些 LP 在区间内"的复杂判断压缩成了一个加减法。不管有一千个还是一万个 LP，跨 Tick 时只读一个数、做一次加法，O(1) 完成。

④ 结合案例看 L 的变化

本案例中 swap 从 Tick 202919 开始，向左移动跨过 Tick 202910：

  • • 区间 [202910, 202920] 内：\(L_1 \approx 15,482,930\)，swap 的 450 USDC 全在这个 L 下执行
  • • 跨 Tick 202910：读取该 Tick 的 liquidityNet → \(L_{\text{new}} = L_1 - \text{liquidityNet}\)
  • • 区间 [202900, 202910] 内：\(L_2 \neq L_1\)，剩余 549.5 USDC 在新区间的新 L 下执行

两段区间 L 不同 → 同样的 Δx 在两个区间换出的 ETH 数量不同（因为滑点不同）。大额交易连续跨越多层区间，这就是为什么 crossedTicks 越大，价格冲击越大。

⑤ LP 添加流动性时 L 怎么算？—— 由投入的代币数量反推

LP 在区间 [Pa, Pb] 投入 x 个 token0 和 y 个 token1，能产生多少 L？取决于当前价格 P 落在哪：

情况 条件 L 计算公式 说明
全 token0 \(P \le P_a\)
价格在区间下方		 \(L = \frac{x}{1/\sqrt{P_a} - 1/\sqrt{P_b}}\) 只需投入 token0，不需要 token1
因为区间内全部是 token0
全 token1 \(P \ge P_b\)
价格在区间上方		 \(L = \frac{y}{\sqrt{P_b} - \sqrt{P_a}}\) 只需投入 token1，不需要 token0
因为区间内全部是 token1
双币 \(P_a < P < P_b\)
价格在区间内		 \(L_x = \frac{x}{1/\sqrt{P} - 1/\sqrt{P_b}}\)
\(L_y = \frac{y}{\sqrt{P} - \sqrt{P_a}}\)
\(L = \min(L_x, L_y)\)		 需要同时投入两种代币
实际 L 取两者最小值
多余的代币会被退还

为什么取 min？因为恒定乘积曲线要求两种代币的比例由价格决定——你投入的 x 和 y 可能不匹配曲线的比例，L 只能取"短板"对应的值，多出的代币退回。

而 每个区间的总 L = 所有覆盖该区间的 LP 仓位的 L 之和。这就是为什么 swap 跨过 Tick 时需要用 liquidityNet 来更新 L——因为不同 LP 的仓位覆盖了不同的区间范围。

3.6 价格与 Tick 的变动方向（容易混淆！）

✅ 合约定义（USDC/WETH 池，token0=USDC, token1=WETH）

\(P = 1.0001^{\text{tick}}\) = 1 USDC 能换到多少 WETH

你用 USDC 买 ETH → 池子 USDC↑、ETH↓ → P 下降 → tick 减小

❌ 普通人直觉（ETH 本位）

大众标价：1 ETH = X USDC

ETH 涨价（3000→3100 USDC）= 1/P 上升 = P 下降 = tick 减小

📌 方向口诀（USDC/WETH 标准池）：

• USDC 买入 ETH：Tick 减小（向左移动）

• ETH 卖出换回 USDC：Tick 增大（向右移动）

四、数学公式详解

4.1 恒定乘积基础（V2）

$$x \cdot y = L^2$$

其中 \(L = \sqrt{k}\)，称为"流动性"。价格 \(P = \frac{y}{x}\)。

在恒定乘积曲线上，交易的"有效价格"随交易量变化（滑点）：

推导：从恒定乘积不变式出发

swap 前后 k 不变：\((x + \Delta x)(y - \Delta y) = x \cdot y\)

展开：\(x y - x \Delta y + \Delta x \cdot y - \Delta x \Delta y = x y\)

消去 xy：\(-x \Delta y + \Delta x \cdot y - \Delta x \Delta y = 0\)

移项：\(\Delta x \cdot y = \Delta y (x + \Delta x)\)

$$\Rightarrow \Delta y = \frac{\Delta x \cdot y}{x + \Delta x}$$

卖出 \(\Delta x\) 个 token0，得到 \(\Delta y\) 个 token1（忽略手续费）

有效成交价 = \(\frac{\Delta y}{\Delta x} = \frac{y}{x + \Delta x}\)，比当前价格 \(P = y/x\) 差——这就是滑点。

4.2 V3 集中流动性数学

V3 流动性仓位定义在价格区间 \([P_a, P_b]\) 内。设当前价格 \(P\)：

虚拟准备金（Virtual Reserves）

V3 的核心技巧：想象"虚拟"的 token0 和 token1 准备金，使得恒定乘积公式在区间内依然成立。

$$(x_{\text{real}} + x_{\text{virtual}}) \cdot (y_{\text{real}} + y_{\text{virtual}}) = L^2$$

虚拟准备金保证曲线在 Pa 处 token1 耗尽（y=0），在 Pb 处 token0 耗尽（x=0）。如何求 \(x_{\text{virtual}}\) 和 \(y_{\text{virtual}}\)？利用边界条件反推：

推导 \(y_{\text{virtual}}\)（利用下边界 Pa，此时 yreal = 0）

价格的定义：\(P = \frac{y_{\text{real}} + y_{\text{virtual}}}{x_{\text{real}} + x_{\text{virtual}}}\)

在 Pa 处 yreal=0，恒定乘积成立：\((x_{\text{real}} + x_{\text{virtual}}) \cdot y_{\text{virtual}} = L^2\)

⇒ \(x_{\text{real}} + x_{\text{virtual}} = \frac{L^2}{y_{\text{virtual}}}\)，代入价格公式：

$$P_a = \frac{y_{\text{virtual}}}{L^2 / y_{\text{virtual}}} = \frac{y_{\text{virtual}}^2}{L^2} \quad\Rightarrow\quad y_{\text{virtual}} = L \cdot \sqrt{P_a}$$

推导 \(x_{\text{virtual}}\)（利用上边界 Pb，此时 xreal = 0）

在 Pb 处 xreal=0，恒定乘积成立：\(x_{\text{virtual}} \cdot (y_{\text{real}} + y_{\text{virtual}}) = L^2\)

⇒ \(y_{\text{real}} + y_{\text{virtual}} = \frac{L^2}{x_{\text{virtual}}}\)，代入价格公式：

$$P_b = \frac{L^2 / x_{\text{virtual}}}{x_{\text{virtual}}} = \frac{L^2}{x_{\text{virtual}}^2} \quad\Rightarrow\quad x_{\text{virtual}} = \frac{L}{\sqrt{P_b}}$$

总结，对于流动性 L 和区间 \([P_a, P_b]\)：

$$x_{\text{virtual}} = \frac{L}{\sqrt{P_b}}, \quad y_{\text{virtual}} = L \cdot \sqrt{P_a}$$

为什么要算 x_real 和 y_real？—— 用途有三个

  • ① 这是 swap 公式的根基：swap 输入 \(\Delta x = x_{\text{real}}(P_{\text{end}}) - x_{\text{real}}(P_{\text{start}})\)，输出 \(\Delta y = y_{\text{real}}(P_{\text{start}}) - y_{\text{real}}(P_{\text{end}})\)。没有 x_real / y_real 就没有 swap 计算。
  • ② LP 需要知道该存多少、能取多少：LP 在价格 P 添加流动性时，x_real(P) 和 y_real(P) 就是该投入的两种代币数量；取出时也是拿回这两个数。
  • ③ 验证边界单边耗尽：代入 P=P_a 得 y_real=0，代入 P=P_b 得 x_real=0，证明了区间两端确实是单边。

当前价格 P 落在区间内时，如何求真实准备金？同时利用恒定乘积和价格定义消去未知项：

推导 \(x_{\text{real}}\) 和 \(y_{\text{real}}\)

已知：\((x_{\text{real}} + x_{\text{virtual}})(y_{\text{real}} + y_{\text{virtual}}) = L^2\) 且 \(P = \frac{y_{\text{real}} + y_{\text{virtual}}}{x_{\text{real}} + x_{\text{virtual}}}\)

由价格定义得 \(y_{\text{real}} + y_{\text{virtual}} = P \cdot (x_{\text{real}} + x_{\text{virtual}})\)，代回恒定乘积：

$$(x_{\text{real}} + x_{\text{virtual}}) \cdot P \cdot (x_{\text{real}} + x_{\text{virtual}}) = L^2$$

$$\Rightarrow (x_{\text{real}} + x_{\text{virtual}})^2 = \frac{L^2}{P} \quad\Rightarrow\quad x_{\text{real}} + x_{\text{virtual}} = \frac{L}{\sqrt{P}}$$

同理：\(y_{\text{real}} + y_{\text{virtual}} = P \cdot \frac{L}{\sqrt{P}} = L \cdot \sqrt{P}\)

代入 \(x_{\text{virtual}} = L/\sqrt{P_b}\) 和 \(y_{\text{virtual}} = L\sqrt{P_a}\)：

$$x_{\text{real}} = \frac{L}{\sqrt{P}} - \frac{L}{\sqrt{P_b}} = L \cdot \left(\frac{1}{\sqrt{P}} - \frac{1}{\sqrt{P_b}}\right)$$

$$y_{\text{real}} = L \cdot \sqrt{P} - L \cdot \sqrt{P_a} = L \cdot \left(\sqrt{P} - \sqrt{P_a}\right)$$

4.3 Swap 计算过程（核心公式）

假设执行 token0 → token1 方向的 swap（如 USDC 买入 ETH），输入 \(\Delta x\) 个 token0。价格从 Pstart 移动到 Pend。

根本公式：从上节的 xreal 和 yreal 直接推出

上节已推导每个区间内的准备金公式（Pa、Pb 是该区间边界，L 恒定）：

$$x_{\text{real}}(P) = L\left(\frac{1}{\sqrt{P}} - \frac{1}{\sqrt{P_b}}\right), \quad y_{\text{real}}(P) = L\left(\sqrt{P} - \sqrt{P_a}\right)$$

Swap 前后价格从 Pstart → Pend，准备金变化量即为 swap 的输入/输出：

$$\Delta x = x_{\text{real}}(P_{\text{end}}) - x_{\text{real}}(P_{\text{start}})$$

$$= L\left(\frac{1}{\sqrt{P_{\text{end}}}} - \cancel{\frac{1}{\sqrt{P_b}}}\right) - L\left(\frac{1}{\sqrt{P_{\text{start}}}} - \cancel{\frac{1}{\sqrt{P_b}}}\right)$$

$$\Rightarrow \boxed{\Delta x = L \cdot \left(\frac{1}{\sqrt{P_{\text{end}}}} - \frac{1}{\sqrt{P_{\text{start}}}}\right)}$$

注意：Pa、Pb 被消去了！只要不跨区间，L 和区间边界都不变，swap 公式与区间边界无关。

$$\Delta y = y_{\text{real}}(P_{\text{start}}) - y_{\text{real}}(P_{\text{end}})$$

$$= L\left(\sqrt{P_{\text{start}}} - \cancel{\sqrt{P_a}}\right) - L\left(\sqrt{P_{\text{end}}} - \cancel{\sqrt{P_a}}\right)$$

$$\Rightarrow \boxed{\Delta y = L \cdot \left(\sqrt{P_{\text{start}}} - \sqrt{P_{\text{end}}}\right)}$$

💡 这就是 V3 swap 计算的全部根基——两条公式，一条算输入，一条算输出。以下所有步骤只是代数变形。

Step 1：已知 Δx 和 L，求新价格 √Pend

从根本公式移项解出 √Pend：

$$\frac{1}{\sqrt{P_{\text{end}}}} = \frac{\Delta x}{L} + \frac{1}{\sqrt{P_{\text{start}}}}$$

$$\Rightarrow \sqrt{P_{\text{end}}} = \frac{L \cdot \sqrt{P_{\text{start}}}}{L + \Delta x \cdot \sqrt{P_{\text{start}}}}$$

Step 2：用新价格计算输出 Δy

将 √Pend 代入 Δy 根本公式：

$$\Delta y = L \cdot \left(\sqrt{P_{\text{start}}} - \sqrt{P_{\text{end}}}\right)$$

Step 3：综合公式（一步到位，不跨区间时使用）

将 Step 1 的 √Pend 代入 Step 2，化简：

$$\Delta y = L\left(\sqrt{P_{\text{start}}} - \frac{L\sqrt{P_{\text{start}}}}{L + \Delta x\sqrt{P_{\text{start}}}}\right) = L\sqrt{P_{\text{start}}} \cdot \frac{\Delta x\sqrt{P_{\text{start}}}}{L + \Delta x\sqrt{P_{\text{start}}}}$$

$$\Rightarrow \boxed{\Delta y = \frac{\Delta x \cdot L \cdot P_{\text{start}}}{L + \Delta x \cdot \sqrt{P_{\text{start}}}}}$$

分子中出现 \(P_{\text{start}}\) 而非 \(\sqrt{P_{\text{start}}}\)——因为分子有两个 √P 相乘。

4.4 跨 Tick 计算

当 swap 的量足够大，价格会触碰到当前区间的边界 tick。此时需要先算出"到边界需要多少输入"。

推导：直接代入 4.3 节的根本公式

4.3 节已推出 swap 输入量与价格变化的关系（token0→token1 方向）：

$$\Delta x = L \cdot \left(\frac{1}{\sqrt{P_{\text{end}}}} - \frac{1}{\sqrt{P_{\text{start}}}}\right)$$

"到达边界"就是把 Pend 替换成边界价格 Pboundary，即得到达边界所需的输入量：

$$\boxed{\Delta x_{\text{cross}} = L \cdot \left|\frac{1}{\sqrt{P_{\text{boundary}}}} - \frac{1}{\sqrt{P_{\text{start}}}}\right|}$$

加绝对值是为了同时适配两个方向（token0→token1 和 token1→token0）。

跨 Tick 后的 L 更新：

L 的更新规则（回顾 3.5 节③）

每个 Tick 上预存了 liquidityNet，跨 Tick 时读出来做一次加减：

从左→右（tick ↑）

$$L_{\text{new}} = L_{\text{old}} + \text{liquidityNet}$$

例：跨 Tick 10（下界，+50）→ 进入区间，L +50

例：跨 Tick 20（上界，−100）→ 离开区间，L −100

从右→左（tick ↓）

$$L_{\text{new}} = L_{\text{old}} - \text{liquidityNet}$$

例：跨 Tick 20（上界，−100）→ L −(−100) = 进入区间，L +100

例：跨 Tick 10（下界，+50）→ L − 50 = 离开区间，L −50

更新后 L 变了，剩余 Δx 用新区间的 L 继续 swap，重复 4.3 节的计算。

判断逻辑：

若 \(\Delta x_{\text{input}} > \Delta x_{\text{cross}}\)：消耗 \(\Delta x_{\text{cross}}\) 到达边界 → 跨 tick → 按方向更新 L → 用剩余输入继续 swap

若 \(\Delta x_{\text{input}} \le \Delta x_{\text{cross}}\)：在区间内完成 swap，不跨 tick，L 不变

4.5 sqrtPriceX96 编码

合约内部存储的不是价格 P，而是 sqrtPriceX96——\(\sqrt{P}\) 的 Q64.96 定点数表示：

$$\text{sqrtPriceX96} = \sqrt{P} \times 2^{96}$$

使用 \(\sqrt{P}\) 而非 P 的原因：swap 计算中反复出现 \(\sqrt{P}\)，存储它避免重复开方运算，大幅节省 GAS。

sqrtPriceX96 与 Tick 的关系

由 3.1 节 Tick 定义 \(P = 1.0001^{\text{tick}}\)，两边直接开平方：

$$\sqrt{P} = \sqrt{1.0001^{\text{tick}}} = \left(1.0001^{\text{tick}}\right)^{\frac{1}{2}} = 1.0001^{\frac{\text{tick}}{2}}$$

再乘以 \(2^{96}\) 即得合约存储的定点数：

$$\text{sqrtPriceX96} = 1.0001^{\frac{\text{tick}}{2}} \times 2^{96}$$

4.6 Tick 计算公式

从价格反推 tick——对 Tick 定义式两边取自然对数：

由 3.1 节：\(P = 1.0001^{\text{tick}}\)

$$\ln P = \ln\left(1.0001^{\text{tick}}\right) = \text{tick} \cdot \ln 1.0001$$

$$\Rightarrow \text{tick} = \frac{\ln P}{\ln 1.0001}$$

tick 必须是整数，向下取整确保 tick 对应价格 ≤ 实际价格：

$$\boxed{\text{tick} = \left\lfloor \frac{\ln P}{\ln 1.0001} \right\rfloor}$$

从 tick 到 sqrtPriceX96：

$$\text{sqrtPriceX96} = \left\lfloor 1.0001^{\frac{\text{tick}}{2}} \times 2^{96} \right\rfloor$$

5.4 逐步计算解析

  1. STEP 1 — 区间 [202910, 202920]

    • 起始 Tick = 202919，落在区间 [202910, 202920] 内

    • 该区间流动性 L₁ ≈ 15,482,930

    • Swap 逐步消耗 USDC，\(\sqrt{P}\) 不断降低，Tick 向左移动

    • 计算到达 Tick 202910 边界需要消耗的 USDC：

    $$\Delta x_{\text{cross}} = L_1 \cdot \left(\frac{1}{\sqrt{P_{202910}}} - \frac{1}{\sqrt{P_{202919}}}\right) = 450 \text{ USDC}$$

    • 消耗 450 USDC，Tick 恰好到达 202910（区间下边界）

  2. ⚡ CROSS Tick 202910

    • 跨越 Tick 边界 → 系统读取该 Tick 上记录的 liquidityNet，一次计算完成两个动作：

    Tick 202910 上累加的 liquidityNet 包含两类仓位：

    \(\text{liquidityNet} = \underbrace{+L_{[202910,\,202920]}}_{\text{下界在这的仓位}} \;\; \underbrace{- L_{[202900,\,202910]}}_{\text{上界在这的仓位}}\)

    从右→左跨（符号取反）：\(L_{\text{new}} = L_{\text{old}} - \text{liquidityNet}\)

    $$= L_{\text{old}} - (+L_{[202910,202920]}) - (-L_{[202900,202910]}) = L_{\text{old}} - L_{\text{旧}} + L_{\text{新}}$$

    • 一次减法同时完成：卸载旧区间 [202910, 202920] 的 L旧  +  加载新区间 [202900, 202910] 的 L新

    • 这是 V3 独有的逻辑，V2 的 L 永不改变

  3. STEP 2 — 区间 [202900, 202910]

    • 当前 Tick = 202910，处于新区间 [202900, 202910]

    • 该区间流动性 L₂ ≠ L₁（不同区间流动性相互独立）

    • 消耗剩余 549.5 USDC（999.5 − 450 = 549.5）

    • 资金全部用完，swap 循环终止。最终 Tick 停在 202900~202910 之间某处

    • 计算总 WETH 输出（两段相加）：

    $$\Delta y_{\text{total}} = \underbrace{L_1\left(\sqrt{P_{202919}} - \sqrt{P_{202910}}\right)}_{\text{STEP 1}} + \underbrace{L_2\left(\sqrt{P_{202910}} - \sqrt{P_{\text{end}}}\right)}_{\text{STEP 2}} = 0.6489 \text{ WETH}$$

5.5 为何 Tick 变小？（买入 ETH 时）

以 USDC/WETH 池为例（token0=USDC, token1=WETH），合约定义的 P = 1 USDC 可以换多少 WETH：

swap 对池子的影响

USDC 买入 WETH → 池子 USDC↑、WETH↓

P = WETH/USDC ↓（USDC 相对贬值）

P↓ → tick↓

ETH 本位视角

ETH 变贵（供应减少）= 1/P 上升

1/P 上升 ⇔ P 下降 ⇔ tick 减小

ETH 越贵，tick 越小

六、手续费机制

6.1 手续费层级与选择策略

Uniswap V3 为同一个交易对提供多个手续费层级的池子，LP 可根据风险偏好选择：

费率 适用场景 LP 策略
0.01% 稳定币对，价格几乎恒定 极窄区间，高交易量补偿低费率
0.05% 主流对（USDC/ETH），波动温和 适度区间，平衡风险和收益
0.3% 普通交易对 标准策略
1% 高波动 / 新兴代币 宽区间，高费率补偿高风险

6.2 手续费计算方式

手续费在 swap 开始前从输入金额中直接扣除——不从输出中扣：

$$\text{amountInAfterFee} = \text{amountIn} \times \frac{1000000 - \text{feeBps}}{1000000}$$

feeBps 以百万分之一为单位（如 500 = 0.05%）。先扣费，再用剩余金额计算 swap 输出。

6.3 手续费分配与领取

手续费按各 LP 在区间内提供的流动性比例实时累积。与 V2 不同，V3 的手续费 不会自动复投（不加入流动性），LP 需通过 collect() 函数手动领取。
