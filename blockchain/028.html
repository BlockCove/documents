1核心概念：Gas、Gwei 与 ETH

Gas 是以太坊虚拟机（EVM）衡量计算工作量的单位。每一条 EVM 指令（加法、存储、合约调用等）消耗固定数量的 Gas。交易费用 = 实际消耗的 Gas × 每单位 Gas 的价格。

当前以太坊存在两个独立的 Gas 市场：

  • 执行层 Gas（Execution Gas）：由 EIP-1559 定义，支付给验证者 + 销毁，用于 EVM 计算和状态变更。
  • Blob Gas（数据可用性 Gas）：由 EIP-4844 定义，全部销毁，用于 Layer2 等场景的大块数据发布。

2EIP-1559 之前：首价拍卖模型及其弊端

在 2021 年 8 月 London 升级之前，以太坊使用简单的首价拍卖（First-Price Auction）模型计算交易费用。用户直接为每单位 gas 出价，矿工按出价从高到低选择交易打包，出价者支付 exactly 自己的报价。

2.1 旧版费用公式

交易费 = gas_used × gasPrice 参数： gasPrice — 用户为每单位 gas 出价的价格（Gwei） gasLimit — 用户愿意支付的最大 gas 量 gas_used — 交易实际消耗的 gas（未用完不收费）

所有交易费全部支付给矿工，没有销毁机制。区块有固定的 gas 上限（由矿工投票逐步调整，如 8M → 12.5M），不存在"目标使用率"或弹性扩容的概念。

2.2 旧版模型的核心弊端

弊端具体表现
首价拍卖低效 用户支付 exactly 其出价，而非市场出清价。理性用户会策略性隐藏真实估价、出价高于必要水平，导致系统性多付。这是机制设计文献中公认的首价拍卖固有缺陷。
费用不可预测 用户必须猜测合适的 gasPrice：出价太低交易卡在内存池数小时甚至数天不被打包；出价太高则显著浪费 ETH。没有协议级的价格参考。
钱包估算不准 钱包基于近期区块的 gasPrice 中位数/百分位估算，但拥堵快速变化时估算迅速过时，导致频繁多付或确认延迟，复杂的估算算法效果有限。
价格剧烈波动 gasPrice 可在区块间剧烈波动（拥堵时可能翻倍），缺乏平滑调整机制，用户难以规划交易成本。
矿工可操纵 矿工可用自己的交易塞满区块、人为推高 gasPrice，因为所有费用直接归矿工，操纵动机强烈且无约束机制。
无通缩机制 所有交易费都支付给矿工，ETH 没有销毁途径，无法通过网络高活跃度产生通缩压力。
固定区块大小 区块 gas 上限固定，没有弹性扩容能力。突发需求只能通过 gasPrice 暴涨来调节，无法临时增加区块容量吸收短期拥堵。

3执行层 Gas：EIP-1559 机制

自 2021 年 8 月 London 升级以来，以太坊执行层交易费由 Base Fee（基础费）和 Priority Fee（优先费/小费）两部分构成。用户在交易中设置两个上限参数：maxFeePerGas 和 maxPriorityFeePerGas。

3.1 实际 Gas 价格与费用公式

effective_gas_price = min(maxFeePerGas, base_fee + maxPriorityFeePerGas) 交易费 = gas_used × effective_gas_price 退款 = (maxFeePerGas − effective_gas_price) × gas_used

其中 gas_used 是交易实际消耗的 Gas（未用完的 Gas 不收费）。Base Fee 部分被销毁，Priority Fee 部分支付给验证者。

3.2 Base Fee 的区块间调整公式

Base Fee 由协议根据上一区块的拥堵程度自动调整，目标是将区块 Gas 使用率维持在 50%（即 target_gas = 15,000,000）。

base_fee_new = base_fee_parent × ( 1 + (gas_used_parent − target_gas) / target_gas / 8 ) 其中： target_gas = 15,000,000 单区块最大变化幅度 = ±12.5%（满块或空块时达到极值）
  • 上一区块 Gas 用量 > 目标 → Base Fee 上涨（最多 +12.5%）
  • 上一区块 Gas 用量 < 目标 → Base Fee 下跌（最多 −12.5%）
  • 恰好等于目标 → Base Fee 不变
图：连续满块（gas_used=30M）时 Base Fee 的指数级上涨轨迹（起始 20 Gwei，示例数据）

3.3 Priority Fee 与交易打包

Priority Fee（小费）是用户支付给验证者的额外费用，用于激励验证者优先打包该交易。验证者在内存池中按 effective_priority_fee = min(maxPriorityFeePerGas, maxFeePerGas − base_fee) 排序，优先选择小费高的交易。

  • 网络空闲时，1–2 Gwei 的小费通常足够；
  • 拥堵时需要提高小费才能在目标区块内被打包；
  • 若 maxFeePerGas < base_fee，交易无法被打包（会一直等待直到 base_fee 下降）。

4Blob Gas：EIP-4844 数据可用性市场

2024 年 3 月 Dencun 升级引入 EIP-4844，为以太坊增加了独立的 Blob Gas 市场。Blob（二进制大对象）是一种临时数据载体，主要供 Layer2 Rollup 发布交易数据使用，成本远低于将数据写入合约存储。

4.1 Blob Base Fee 指数定价公式

与执行层的线性调整不同，Blob Base Fee 采用指数定价，基于累计的 excess_blob_gas（超出目标的累计 Blob Gas）计算：

blob_base_fee = MIN_BASE_FEE_PER_BLOB_GAS × exp( excess_blob_gas / BLOB_BASE_FEE_UPDATE_FRACTION ) 其中： MIN_BASE_FEE_PER_BLOB_GAS = 1 wei excess_blob_gas 每区块更新： excess_new = max(0, excess_parent + blob_used_parent − target_blob_gas)

excess_blob_gas 是一个"拥堵累积器"：当区块持续超过目标时累积增长，Blob Base Fee 随之指数上升；当需求回落时逐渐衰减。

图：Blob Base Fee 随 excess_blob_gas 增长的指数曲线（纵轴为 Gwei，示例数据）

4.2 Blob 交易总费用

blob_fee = blob_gas_used × blob_base_fee 其中 blob_gas_used = blob_count × 131,072 Type 3 交易总费用 = 执行层费用 + Blob 费用 （Blob 费用全部销毁，无 priority fee 组件）

用户在 Type 3 交易中设置 maxFeePerBlobGas 作为 Blob Gas 单价上限。实际支付 = min(maxFeePerBlobGas, blob_base_fee)，超出部分退款。

为什么 Base Fee 要销毁？

  • 防止验证者操纵：若 Base Fee 归验证者，验证者有动机通过塞满区块推高 Base Fee；销毁后验证者只能从 Priority Fee 获利，与区块填充度脱钩。
  • 通缩效应：销毁的 ETH 永久退出流通，在高活跃度时期以太坊可能进入净通缩。
  • 可预测性：Base Fee 由协议公式确定，用户可精确预估下几个区块的费用区间。

9实践建议与常见误区

场景建议
普通转账不着急 maxPriorityFee 设 1–2 Gwei，maxFee 设 base_fee 的 1.5–2 倍即可；交易可能等 1–数个区块。
需要快速确认（如 DeFi 交易） 提高 maxPriorityFee 到 3–5 Gwei 或更高；maxFee 给足余量避免 base_fee 上涨导致交易卡住。
maxFee 设太低会怎样？ 若 maxFee < 当前 base_fee，交易无法打包，会一直停留在内存池直到 base_fee 降到 maxFee 以下。可通过替换交易（相同 nonce，更高 gas）加速或取消。
gasLimit 设太高浪费吗？ 不浪费。只按实际 gas_used 收费，未使用部分不收费。但设太低会导致交易失败（out of gas）且已消耗的 gas 不退。
Layer2 发布数据 使用 Type 3 交易携带 blob，成本远低于 calldata；关注 blob_base_fee，在低峰期发布可显著降低成本。
EIP-7702 gas 赞助 Pectra 后 EOA 可临时附加合约代码，允许第三方支付 gas（gas sponsorship），用户无需持有 ETH 也能交易。
