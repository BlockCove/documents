cast run 高频用法

cast run <tx_hash> 把已经上链的交易在本地重放一遍，并打印调用树（trace）。用来查 revert 原因、看内部调用、核对 gas，而不是发新交易。

本仓库 RPC 别名：

  • --rpc-url local → http://127.0.0.1:8545（foundry.toml）
  • --rpc-url sepolia → .env 里 FOUNDRY_RPC_ENDPOINTS 注入的 Sepolia 节点
source .env   # 加载 RPC 别名和 ETHERSCAN_API_KEY

官方参考：cast run

默认行为（先记住这一条）

默认会先重放同一区块里、这笔交易之前的所有交易，再执行目标交易。这样状态和链上一致，但慢。

模式 速度 准确度 要求
默认本地重放 慢（整块 replay） 最高 普通 RPC 即可
--quick 快 可能不准 普通 RPC
--prestate-tracer 快 接近链上 节点开 debug_
--debug-trace-transaction 最快 就是链上发生的事 节点开 debug_；无 opcode 细节

公共 RPC 大多没有 debug_。Archive / 自建节点、Alchemy、部分付费节点才有。debug_ 不可用时，--prestate-tracer 会静默退回整块 replay。

高频配方

把下面的 0xTX 换成真实交易哈希。

1. 默认重放（最常用） 

cast run 0xTX --rpc-url sepolia

trace 里每一行大致是：[gas] 合约::函数(...) [call 类型] → 返回值 / revert。缩进表示调用深度。

2. 查失败交易 

cast run 0xTX --rpc-url sepolia --la

--la（--with-local-artifacts）用当前 Foundry 项目的编译产物解码函数、事件、自定义 error。本仓库自己部署、浏览器上未验证的合约，必须加这个。

解码仍糊时再补 Etherscan：

cast run 0xTX --rpc-url sepolia --la --etherscan-api-key $ETHERSCAN_API_KEY

3. 先快速看一眼：--quick 

cast run 0xTX --rpc-url sepolia --quick

只用上一块结束时的状态执行这笔交易，跳过同块前置交易。同一块里若有人对同一账户/池子写过状态，结果会和链上不同。确认 revert 原因后再用默认模式复核。

4. 给地址贴标签 

cast run 0xTX --rpc-url sepolia --la \
  --label 0xToken:MyTokenV1 \
  --label 0xBank:TokenBankV1 \
  --compact-labels

--label 可重复。--compact-labels 有标签时隐藏原始地址，trace 更短。地址也可从 deployments/<Name>/<Name>_<chainId>.json 抄。

5. 看内部函数：--decode-internal 

cast run 0xTX --rpc-url sepolia --la --decode-internal

把合约内部调用和栈参数解出来。bytes / 数组等内存参数只在匹配到唯一函数时解码（和 --debug 一样，为了性能）。

调用树太深时限深度：

cast run 0xTX --rpc-url sepolia --la --trace-depth 8

6. 进交互式调试器：--debug 

cast run 0xTX --rpc-url sepolia --la --debug

终端 TUI：源码、opcode、变量、栈、memory/calldata。常用键：j/k 单步，C/c 下一个/上一个 call，q 退出。完整键位见 Forge debugging。

本仓库未验证的合约，没有 --la 时调试器对不上源码。

7. 走节点 trace（有 debug_ 时） 

# 不本地执行，直接渲染节点 callTracer（嵌套调用 / value / gas / log / revert）
cast run 0xTX --rpc-url sepolia --debug-trace-transaction

# 仍本地执行，但用 debug_traceTransaction 拉 prestate，避免整块 replay
cast run 0xTX --rpc-url sepolia --prestate-tracer --la

--debug-trace-transaction 不能和 --debug、--decode-internal、--trace-printer、--quick、--prestate-tracer、--evm-version 一起用。它快、反映链上真实行为（含本地 replay 可能对不齐的链特定 EVM），但没有 opcode 级细节。

8. 本地 anvil 上的交易 

anvil   # 另一个终端
cast run 0xTX --rpc-url local --la

本地没有 Etherscan，解码几乎全靠 --la。

9. opcode 级跟踪（偶尔才用） 

cast run 0xTX --rpc-url sepolia --trace-printer

输出极长，适合核对某条 SSTORE / CALL，不适合日常扫 revert。

怎么选

你想做的事 命令
这笔 tx 为什么 revert cast run 0xTX --rpc-url sepolia --la
先快看，再精确复核 先 --quick，再去掉 --quick
读自己的合约名 / 自定义 error --la，必要时再加 --label
单步源码 --la --debug
内部函数参数 --la --decode-internal
节点有 debug_，只想要调用树 --debug-trace-transaction
节点有 debug_，还要本地 opcode / debugger --prestate-tracer --la
公共 RPC、要和链上完全一致 默认（不要 --quick）

和邻近命令的分工

命令 作用
cast run 0xTX 重放已上链交易，打 trace
cast tx 0xTX 看 from / to / data / value
cast receipt 0xTX 看 status / gasUsed / logs
cast call --trace 模拟还没发的调用
cast 4byte-decode 0x... 只解码 calldata，不执行

典型顺序：cast receipt 确认失败 → cast tx 看 calldata → cast run --la 看调用树。

常见坑

  1. --quick 和链上不一致
    同块前面的交易改过余额、allowance、池子储备。要对齐链上，去掉 --quick。

  2. 公共 RPC 没有 debug_
    --debug-trace-transaction 会失败；--prestate-tracer 会退回整块 replay，看起来“没加速”。

  3. trace 里全是 4byte 选择器
    合约未验证，或没加 --la。本仓库部署请始终 --la。也可先 forge selectors cache 把本地 selector 写进全局缓存。

  4. 默认模式很慢 / 超时
    块里交易多时整块 replay 会打满 RPC。提高 --rpc-timeout，或换 archive / 带 debug_ 的节点后用 --prestate-tracer。

  5. --debug-trace-transaction 打不开调试器
    它只渲染节点 call tree，不走本地 EVM。要 TUI 调试器用默认 replay 或 --prestate-tracer，再加 --debug。

  6. L2 系统交易
    部分 L2 需要 --replay-system-txes 才能对齐块内状态。Sepolia L1 一般不用。
